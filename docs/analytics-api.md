# Сохранённые рекомендации, справочники и аналитика

Чтение выполняется из БД через application use cases. Значения количеств, цен,
долей и порогов сериализуются десятичными строками. Недостающие цены и остатки
возвращаются как `null`; текущие условия поставщика не используются для оценки
исторического запуска.

## Запуски и рекомендации

`GET /api/calculation-runs` поддерживает `status`, `warehouse_id`, `category_id`,
`limit=1..100`, `offset>=0`. Порядок — `started_at DESC`, затем ID для стабильной
пагинации. Ответ содержит `items`, `total`, `limit`, `offset`.

`GET /api/calculation-runs/{id}/recommendations` применяет все фильтры, поиск
`search` по SKU/наименованию и пагинацию на сервере. `%` и `_` в поиске означают
обычные символы. Строка содержит SKU, название, единицу, названия поставщика,
склада и категории, а также `unit_price`, `currency`, `estimated_total`.
Названия берутся из справочников; финансовые поля — только из сохранённого
`calculation_details.supplier_terms_snapshot`. Для старых запусков без снимка
цена, валюта и сумма остаются `null`.

При создании нового запуска в `calculation_runs.parameters.supplier_terms_snapshot`
фиксируются исходные условия поставщиков. Pipeline читает этот снимок и сохраняет
условия выбранного поставщика в рекомендации. В поле `unit_price` рекомендации
содержится закупочная цена; итоговая оценка равна цене, умноженной на текущее
`effective_quantity`. Ручная корректировка меняет количество и сохраняет снимок цены.

## Справочники

`GET /api/v1/suppliers` принимает `active_only=true`, `search`, `limit=1..500`,
`offset>=0` и возвращает страницу. `GET /api/v1/warehouses` и
`GET /api/v1/categories` принимают `active_only` и `search`, возвращают `items`.
Элементы содержат `id`, `code`, `name`, `is_active`; категория также `parent_id`.

## История рекомендации

`GET /api/recommendations/{id}/history?months=24` принимает 1–24 месяца и возвращает
`recommendation_id`, `run_id`, `points: [{month, sales, stock}]`. Используются только
ID импортов, связанные с завершённым запуском, и его `source_cutoff_at`. Источник
продаж соответствует `demand_source` запуска. Транзакционные продажи включают
возвраты с их отрицательным знаком. Месячные агрегаты не распределяются по дням.

Остаток — последнее наблюдение в соответствующем месяце; отсутствие наблюдения
означает `null`. Перенос остатка из предыдущего месяца не выполняется. Месяцы
без обоих источников пропускаются. Для источника месячных агрегатов также
пропускается месяц без записи продаж: отсутствие записи не считается нулём.

## Аномалии

`GET /api/v1/analytics/outliers` требует `calculation_run_id` и поддерживает
`supplier_id`, `product_id`, `warehouse_id`, `category_id`, `limit=1..100`, `offset>=0`.
Ответ — страница аномалий конкретного запуска с SKU, датой продажи, методом,
исходным/замещающим количеством, порогом и причиной. Клиентские идентификаторы,
контакты и номера документов в ответ не входят. Список содержит транзакционные
аномалии `detected_anomalies`; месячные `period_anomalies` остаются частью
сохранённого объяснения и не выдаются за транзакционные записи.

## Ряд спроса и ABC/XYZ

`GET /api/v1/analytics/demand-series` требует `calculation_run_id` и принимает
`supplier_id`, `warehouse_id`, `category_id`, `product_id`, `months=1..24`.
Ответ содержит сохранённые `raw_sales`, `cleaned_demand` и `stock` по месяцам,
`algorithm_version` и `available_months`. В версии `mvp-2` расчёт сохраняет
12 месяцев; запрос 24 месяцев возвращает доступные месяцы без искусственного
расширения ряда. Если у любой составляющей агрегата нет наблюдения остатка,
общий остаток за месяц — `null`. Категория читается из снимка прогноза.

`GET /api/v1/analytics/abc-xyz` требует `calculation_run_id` и принимает
`supplier_id`, `warehouse_id`, `category_id`. Ответ содержит девять ячеек
`{abc, xyz, sku_count, demand_share}`, версию алгоритма и `metadata` с методом
и порогами из `calculation_runs.parameters.analytics_policy`.

Версия `demand-quantity-abc-xyz/v1` использует количество очищенного спроса, а не
денежную выручку: A — до 80% накопленной доли, B — до 95%, C — остаток. SKU,
пересекающий границу, включается в предыдущий класс. X/Y/Z определяются
популяционным коэффициентом вариации по календарным месяцам: X ≤ 0,10,
Y ≤ 0,25, Z > 0,25. SKU с нулевым спросом относится к C/Z. При фильтрации
доли вычисляются относительно выбранного набора. Количественное сравнение
разных единиц измерения требует бизнес-интерпретации; оно не является ABC
по выручке.

Для старых запусков без сохранённого ряда или политики возвращается 422
`analytics_unavailable`. Незавершённый запуск даёт 409, неизвестный ID — 404.
Повторное чтение аналитики не запускает pipeline и не меняет рекомендации.
